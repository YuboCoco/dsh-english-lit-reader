# 参考文献改进方案 · 由 DeepSeek 直接解析

## 给 DeepSeek 的实施任务

请在当前 `dsh-english-lit-reader` 仓库实施本方案。用户点击「论文分析」时，用同一个入口启动正文总结和参考文献识别。**由大模型识别参考文献区段、逐条分段、提取书目信息及原文地址。** 第一批通过核验的条目立即显示。缺少地址的条目再调用 Crossref，查到后逐批回填。保留「参考文献」页签的单独整理、重试和旧缓存读取入口。

当前仓库已有分阶段接口。`client.js` 的 `doSummary()` 已调用 `doReferences()`，后者调用 `/references/segment`、`/references/fields` 和 `/references/resolve`。`index.js` 的 `/references/segment` 仍先用 `locateReferenceLines()` 和 `segmentReferenceEntries()` 裁剪、拆分，只有规则返回 `unsplit` 才尝试模型。规则切错区段或误切成多条时，模型已经拿不到正确的输入。此次应把**区段和条目边界的决定权交给模型**，并复用已有的逐步显示、链接查询和缓存。

## P0　切换为模型解析

1. **给模型提供带位置的原文。** 复用现有 PDF.js 文本提取，保留页码、换行和稳定行号。双栏 PDF 尽量按栏保留阅读顺序，包含跨页续行。粘贴文本也生成稳定行号。保留已有的正文总结输入和输出格式。
2. **按页或行窗口请求模型。** 可从靠后的页面和疑似 `References` 标题附近开始，保留前后上下文。标题、作者格式、编号和附录标记可以帮助选择先看哪里。模型负责判断窗口里的参考文献区段，排除正文、目录、附录中的公式编号、标题和步骤。末尾只看到附录、只看到跨页残段或疑似目录时，扩大覆盖范围继续检查。相邻窗口保留重叠行。窗口预算用尽时显示覆盖范围和「部分完成」，支持继续；扫描版没有可提取文本时提示 OCR 或粘贴参考文献。
3. **一次模型调用输出一批条目。** 要求模型按原文顺序返回 `startLine`、`endLine`、`number`、`title`、`firstAuthor`、`year`、`venue`，同时摘录属于该条的 `printedAddress`（原文 URL、DOI 或 arXiv ID）。允许编号或字段为空。要求标记窗口边缘的不完整条目，下一窗口补齐；作者姓名和题名必须来自引文，正文提到但未列出的论文不录入。输出含 `entries` 数组和未完成边界的 JSON 对象。现有模型接口支持结构化输出时可启用，否则校验文本 JSON。
4. **由程序核验和合并。** 用返回的行范围回切原文，验证范围合法、可追溯，并从来源位置生成稳定条目 ID。按文档顺序合并，去掉重叠窗口产生的同源重复，保留文献表中确实出现多次的引文。相互冲突的范围交给重试或标记待确认。逐批回填，某批超时或 JSON 无效时保留已展示结果，限次重试受影响的窗口，必要时缩小窗口。区分「没有确认到参考文献」与「识别中断或覆盖不全」。
5. **复用 Harness 模型配置。** 在 `/references/segment` 的用户主路径调用现有 `runModel()`。尊重用户选择的模型和推理档位，默认选择可复用 `resolveEffectiveModel()`。正文总结和参考文献在同一按钮触发，保留各自的完成状态；同一模型服务的并发按现有调度能力控制，参考文献的失败不取消正文总结。

## P1　让每个地址都可追溯

| 地址来源 | 实施要求 | 界面状态 |
| --- | --- | --- |
| 引文原文印有 DOI、arXiv ID 或 URL | 核对模型摘录确实属于该条引文。对原文 DOI 或 arXiv ID 生成标准链接，对原文 URL 只接受有效的 HTTP(S) 地址。跨行折断只在能从原文无歧义恢复时合并。 | 原文提供 |
| 原文没有可用地址 | 复用 `/references/resolve`，用模型从原文提取的标题、第一作者和年份查询 Crossref，结合来源等信息匹配。标题比较要考虑两边都覆盖到的内容，保留可能区分论文的数字和缩写。 | 已匹配、待确认或无匹配 |
| 模型给出一个来源不明的地址 | 将它视为尚无可用地址。只有能定位到原文，或通过查询匹配到同一篇文献的地址，才显示为可点击结果。 | 待确认或无匹配 |
| Crossref `429`、超时或服务端错误 | 限制并发，对可恢复的错误有限退避。缓存高置信命中并合并相同查询，重试只处理临时失败或尚未处理的条目。 | 查询暂时失败 |

仓库现有 `runModel()` 通过 `llm.stream()` 接收文本，参考文献地址检索已有 Crossref 路由。即使模型认得某篇论文，仅凭模型输出的 DOI 或 URL 也不足以证明地址正确。若将来接入模型可用的检索工具，链接应附可核验的检索来源，并继续检查标题、作者、年份与原引文是否对应。

## P2　接入回填、取消和缓存

- `/references/segment` 在主路径返回模型提取的条目和字段。`/references/fields` 复用来补缺失字段或翻译标题，跳过已获取的字段。标题译文与链接异步回填，不阻塞英文原文展示。保留旧 `/references` 调用和旧缓存读取。
- 沿用 `doReferences()` 中的论文 ID 和请求序号，并用输入版本防止编辑后旧响应覆盖新结果。切换、关闭论文或启动新任务后，旧响应不得更新当前面板或写入其他论文。重复触发同一论文、同一输入时复用进行中的任务。
- 在同一输入内按来源位置或已核验的标识合并缓存。旧缓存的数组下标不能作为条目对应关系，历史 `found` 值不能直接当作新版已匹配状态。新增状态文案时同步 `client.js` 内联字典与 `locale/en.json`、`locale/zh.json`。

## 验收清单

| 用例 | 通过条件 |
| --- | --- |
| 点击「论文分析」 | 正文总结和参考文献都启动；编号目录也由模型解析；第一批经核验的条目可先读，独立整理入口可用。 |
| 双栏、跨页、无编号和无标题目录 | 逐条比对人工标注，目录条数、顺序及原文范围一致；相邻窗口无重复或漏掉的跨页条目。 |
| 参考文献后有长附录、定理或编号步骤 | 扩大窗口能找到前面的参考文献，附录内容不进入目录。 |
| 81 条及更长的目录、模型超时或 JSON 截断 | 已成功批次保留，只重试受影响的范围；覆盖不全有可见提示和继续入口。 |
| DOI、arXiv ID 或 URL 印在条目中 | 可回查至对应原始引文，展示原文地址且无需搜索。 |
| 模型输出貌似有效但原文未提供的链接 | 链接只有在检索确认后才可点击。原论文、同名论文、综述和版本冲突的样例无错链。 |
| Crossref 限流、超时和无匹配 | 状态可区分，已显示的文献保留，重试只处理需要重试的条目。 |
| 发起 A 后切换到 B、重复触发、重开缓存 | 界面和缓存不串论文，重复请求合并，旧结果可读。 |

先运行 `node --check index.js` 和 `node --check client.js`。用模拟模型和 Crossref 响应覆盖故障，再用同一组人工标注的真实 PDF 对照改动前后的**条目召回率、错链数、首批可读时间、模型调用次数和 Crossref 请求次数**。首批可读时间从点击入口计到第一批原文条目可读。交付时记录已通过的场景及需要在真实 Harness 中复核的项目。
