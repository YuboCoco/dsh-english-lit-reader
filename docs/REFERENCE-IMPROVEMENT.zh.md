# DeepSeek Harness 英文阅读插件参考文献改进方案

## 给 DeepSeek 的实施任务

请在当前 `dsh-english-lit-reader` 仓库实施下述改动。先读 `client.js`、`index.js`、`locale/en.json` 和 `locale/zh.json`，确认当前入口和数据结构，再按 P0、P1、P2 的顺序修改和验证。范围是现有「参考文献」栏的目录提取、标题翻译和地址查询。保留手动整理、点击「论文分析」时自动整理、重新打开论文时恢复结果等入口。

目标行为是**先显示原文条目，再逐批补充链接和中文标题**。原编号和原文应始终可核对。地址服务或模型出现故障时，已提取的条目仍然可读。

## 已复现的问题与相关代码

| 问题 | 当前行为 | 入口 |
| --- | --- | --- |
| 文献遗漏或混入正文 | PDF 提取用空格拼接一页内的所有文本片段。短文直接送入模型，长文只取末尾 40,000 字符。本地样例中，参考文献后接很长的附录时，参考文献被完全裁掉。 | `client.js` 的 `extractText()`，`index.js` 的 `referenceTail()` |
| 长列表缺条或全空 | 模型一次生成整份 JSON 数组。81 条被截成 80 条，少一个结束方括号时结果变成 0 条。 | `index.js` 的 `REFERENCES_SYSTEM`、`parseReferenceArray()` 和 `/references` |
| 错链或查不到 | 原文 DOI 未被优先使用。按较短标题计算覆盖率，会使标题包含另一标题的综述得到满分。模拟 HTTP `429` 与成功响应无匹配时，接口返回相同状态。 | `index.js` 的 `crossrefRequest()` 和 `titleScore()` |
| 等待过长和结果串页 | 前端等整个请求结束才显示结果，响应完成时按当时的 `paperIdRef.current` 保存。切换论文后，旧请求有机会更新新论文的界面和缓存。 | `client.js` 的 `doReferences()` 和结果保存逻辑 |

本地复现使用合成文本、模拟模型和模拟 Crossref 响应。真实 PDF 的召回率和 Harness 内的耗时需要实施后测量。

## P0　让原文列表先显示

1. 在现有 PDF.js 提取路径复用 `getTextContent()`，为参考文献保留 `hasEOL`、位置和页码。用换行和坐标重建行，双栏页按栏恢复阅读顺序，保留跨页条目的续行。沿用当前供全文分析和翻译使用的文本输入。
2. 在页面序列中定位 `References`、`Bibliography`、`Works Cited` 等独立标题。结合后续行是否像参考条目，排除目录、页眉和正文提及。在明确的下一节标题处结束，比如 `Appendix` 或 `Supplementary Material`。标题找不到时，可从连续的编号或作者—年份模式判断候选区段。定位仍不可靠时，给出清晰提示并支持从参考文献页或粘贴的目录文本重试。扫描版无文本时提示 OCR 或粘贴目录。
3. 对 `[1]`、`1.` 等编号格式优先按行首及编号序列分条。为每条生成稳定的 `id`，保留原编号、页码范围、原文和原有排列。未能拆分的区段保留原文并提示待整理。处理长列表时按条目或页面边界分批，取消静默的 80 条截断。超过单次处理预算时标记尚未处理的范围，支持继续处理。
4. 提取完成就显示条目，地址和中文标题随后按 `id` 回填。请求发出时记录论文 ID、输入版本和请求序号。切换论文、关闭论文、编辑输入或启动新任务时，失效的响应不得更新当前界面或写入其他论文缓存。相同论文和输入的自动触发与手动触发共用进行中的整理任务。
5. 从可归属到单条引文的原文中提取 DOI 或 arXiv ID。对符合格式的标识生成标准链接，标注「原文提供」。识别跨行折断和句末标点时保留原文，无法可靠恢复的标识进入后续查找。原文提供的链接可以随条目立即显示。

## P1　提高链接匹配质量并缩短等待

1. 只对缺少可用原文标识且未命中缓存的条目调用 Crossref。以标题和第一作者为主要查询信息，补充年份及期刊或会议。标题归一化应保留会改变身份的数字、缩写和关键词。采用双向标题覆盖或类似的双向比较，结合作者、年份和候选间分差判断。相似标题、多个强候选或版本冲突时显示「待确认」。
2. 分别记录「原文提供」「已匹配」「无匹配」「待确认」「暂时失败」。将 `429`、服务端错误和网络超时归入暂时失败。按 Crossref 返回的限流信息控制并发，对可恢复错误有限退避，给每批查询设定总时限。失败或超时只影响当前批次，后续批次和原文列表仍可用。
3. 按条目 ID 逐批更新页面。相同查找合并请求，缓存高置信命中结果。「重试失败项」只重跑暂时失败或尚未处理的条目，保留已完成结果。旧版缓存仍可读取，新版可按原文标识和查询结果记录来源；旧缓存中的 `found` 值不能自动视为经过新版匹配规则验证。

## P2　用 DeepSeek 补齐难解析条目和中文标题

1. 清楚的编号条目直接进入列表。只给模型发送参考文献候选区段或待补字段的原文。若条目边界还不明确，先给源文本行编号，要求模型返回对应的行范围，再由程序据此生成条目并保留原文。模型输出的范围须按原顺序、无重叠、可回溯。
2. 字段抽取和标题翻译以每批约 **8–12 条**作为初始参数，并限制批次字符数。每条带固定 ID，只返回需要补充的标题、作者、来源、年份或译文。逐条校验 ID、字段类型和重复项，从原文核对抽取字段。成功项立即回填，缺失或无效项只做有限重试。整批 JSON 无效时，可缩小该批重新请求，其他批次照常保留。
3. 默认模型可复用现有 `resolveEffectiveModel()` 的快速模型选择机制，尊重用户明确选定的模型和推理档位。中文标题异步补齐，超时或错误时保留英文标题及原始引文。

## 接入约定

- 复用现有参考文献页签和模型设置。客户端可通过独立阶段请求实现提取、地址查询和翻译的逐批回填。若调整路由，兼容已有 `/references` 调用与旧缓存中 `en`、`zh`、`venue`、`year`、`found`、`url` 等字段。
- 新增界面文案时，同时更新 `client.js` 内联词典及 `locale/en.json`、`locale/zh.json`。状态提示要能区分目录未定位、部分条目待处理和地址查询暂时失败。
- 检查 `titleMatches()` 和共享模型、文本提取函数的其他调用方，避免参考文献的匹配规则影响其他功能。优先复用现有 PDF.js 和 Harness 服务。

## 验收清单

| 用例 | 通过条件 |
| --- | --- |
| 单栏 PDF、双栏 PDF、跨页条目 | 对照人工标注，符合支持范围的编号目录条数和顺序一致，保留原编号和页码。 |
| 参考文献后接长附录 | 保留完整目录，附录内容不会被当作条目。 |
| 81 条及更长的目录 | 条目完整，或明确显示已处理范围及继续处理入口。 |
| 作者—年份格式、无标题目录、扫描版 | 分条结果可追溯至原文，无法可靠定位时有明确提示和可操作的重试方式。 |
| 原文含 DOI 或 arXiv ID | 首批条目能直接显示相应链接，验证未为这些条目发标题搜索请求。 |
| 同名论文、综述后缀、预印本与正式版 | 有充分证据才自动链接，冲突时标记待确认。固定错链回归样例应为零错链。 |
| Crossref `429`、超时、无匹配 | 状态可区分，已显示条目保留，重试从暂时失败或未处理的条目恢复。 |
| 模型 JSON 截断、漏返或重复 ID | 保留原文和已成功批次，只重试受影响的批次或条目。 |
| 发起 A 后切换到 B、同一论文重复触发、重开旧缓存 | 旧响应不会覆盖当前论文或其他论文缓存，重复请求被合并，历史结果仍可读。 |

用同一批人工标注 PDF 记录改动前后的**条目召回率、错链数、首批条目显示时间、外部请求数**。首批显示时间从点击入口计到原文条目可读，不含中文标题和所有地址补齐的等待。分别检查冷缓存和重开论文两种情况。至少运行 `node --check index.js` 和 `node --check client.js`，并用本地测试或模拟响应复现表中适用的故障。交付时说明完成了哪些阶段、修改了哪些文件、哪些场景已验证，以及哪些仍需在真实 Harness 中测量。
